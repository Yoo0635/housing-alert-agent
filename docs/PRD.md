## 1. 배경 및 문제 정의

- SH(서울주택도시공사), GH(경기주택도시공사), LH(한국토지주택공사)에는 분양·임대 공고가 수시로 올라온다.
- 지금은 세 사이트에 **매일 직접 들어가서** 새 공고가 있는지 찾아봐야 해서 번거롭고, 놓치는 공고가 생길 수 있다.
- Slack은 **무료 플랜이라 메시지 기록이 오래 남지 않는다** (무료 플랜은 최근 90일만 열람 가능). 그래서 알림만으로는 공고 이력을 오래 보관할 수 없다.

## 2. 목표

| # | 목표 | 성공 기준 |
|---|---|---|
| G1 | SH·GH·LH 신규 공고를 자동으로 감지 | 매일 정해진 시간에 세 기관의 공고 목록을 확인하고 새 공고를 빠짐없이 감지 |
| G2 | 새 공고가 생기면 바로 알림 | 감지한 신규 공고를 Slack으로 전송 |
| G3 | 공고 이력을 오래 보관 | 모든 신규 공고를 Obsidian 볼트에 Markdown 노트로 누적 저장 |
| G4 | 중복 없는 알림 | 이미 알린 공고를 다시 보내지 않음 |

## 3. 비목표 (이번 범위에서 제외)

- 청약 신청 자동화 (신청은 사용자가 직접 한다)
- 여러 사용자를 위한 서비스화 (회원가입, 사용자별 설정 등)
- 모바일 앱이나 웹 대시보드

## 4. 사용자

- **주 사용자: 본인 1인.** 서울·경기권 공공주택(분양/임대) 공고를 챙겨보는 사람.
- 사용 환경: Slack(무료 플랜), Obsidian, macOS

## 5. 사용자 시나리오

1. 에이전트가 매일 정해진 시간에 자동으로 실행된다.
2. SH·GH·LH 공고 게시판(또는 API)을 조회한다.
3. 이전에 저장한 공고와 비교해서 새 공고만 골라낸다.
4. 새 공고가 있으면:
   - Slack 채널로 요약 메시지를 보낸다 (기관, 제목, 공고일, 링크).
   - Obsidian 볼트에 공고별 Markdown 노트를 만든다.
5. 사용자는 Slack 알림을 보고 링크로 원문을 확인한다. 지난 공고는 Obsidian에서 검색해서 찾아본다.

## 6. 기능 요구사항

### F1. 공고 수집 (Collector)

| 기관 | 수집 대상 (후보, 확인 필요) | 비고 |
|---|---|---|
| SH | SH 인터넷청약 / 공고 게시판 (i-sh.co.kr) | HTML 크롤링 예상 |
| GH | GH 공고 게시판 (gh.or.kr) | HTML 크롤링 예상 |
| LH | LH청약플러스 (apply.lh.or.kr) 또는 공공데이터포털 "LH 분양임대공고문 조회" API | API를 쓸 수 있으면 API 우선 |

- 기관마다 수집기를 따로 두어, 사이트 구조가 바뀌어도 해당 기관 수집기만 고치면 되게 한다.
- 수집 항목 (공통 스키마):
  - `source` (SH / GH / LH)
  - `id` (기관 내 고유 공고번호, 없으면 URL로 대신함)
  - `title` (공고 제목)
  - `category` (분양 / 임대 / 기타, 판별 가능하면)
  - `posted_at` (게시일)
  - `deadline` (접수 마감일, 있으면)
  - `url` (원문 링크)
  - `attachments` (첨부파일 링크, 있으면)

### F2. 신규 공고 판별 (Dedup)

- 지금까지 처리한 공고 ID를 상태 파일(예: JSON 또는 SQLite)에 저장한다.
- `source + id` 조합으로 새 공고인지 판단한다.
- 처음 실행할 때는 기존 공고를 모두 "이미 본 것"으로 등록하고, 알림은 보내지 않거나 최근 N일 공고만 보낸다 (결정 필요).

### F3. Slack 알림 (Notifier)

- **Slack MCP** (공식 Slack 커넥터, `https://mcp.slack.com/mcp`)의 `slack_send_message`로 지정한 채널에 메시지를 보낸다. Webhook은 쓰지 않는다.
- 필요하면 `slack_read_channel`로 최근 알림을 확인해서 중복 전송을 한 번 더 막을 수 있다.

#### 채널 구조

Slack에는 폴더가 없어서, 채널 이름 앞에 `주택공고-`를 붙여 한 묶음(패키지)처럼 관리한다. 이름순으로 정렬하면 사이드바에서 한곳에 모인다.

```
주택공고-
├── 전체     ← 실행 1회당 요약 1건 (오늘 새로 올라온 공고 목록)
├── sh       ← SH 공고 상세 (1건 = 메시지 1개)
├── gh       ← GH 공고 상세
├── lh       ← LH 공고 상세
└── 시스템   ← 수집 실패, 사이트 구조 변경 의심 같은 운영 알림
```

| 채널 | ID | 용도 | 보내는 시점 |
|---|---|---|---|
| #주택공고-전체 | `C0CBWQ7M8E5` | 그날의 신규 공고 요약 (기관별 개수와 제목) | 신규 공고가 있을 때 |
| #주택공고-sh | `C0CBUMSFQQJ` | SH 공고 상세 | SH 신규 공고마다 |
| #주택공고-gh | `C0CBDG3A4KZ` | GH 공고 상세 | GH 신규 공고마다 |
| #주택공고-lh | `C0CCP8T1LL8` | LH 공고 상세 | LH 신규 공고마다 |
| #주택공고-시스템 | `C0CBSUD75AA` | 오류와 운영 로그 | 수집이나 저장에 실패했을 때 |

- 기관 채널 안에서는 메시지 첫 줄에 유형 태그를 붙여 한 번 더 나눈다: `[분양]`, `[임대]`, `[기타]`. 나중에 Slack에서 `in:#주택공고-lh [임대]`처럼 검색할 수 있다.
- 기관이 늘어나면 같은 규칙으로 `주택공고-<기관>` 채널을 추가한다 (예: `주택공고-ih`).
- Slack 사이드바에서 "주택공고" 섹션을 만들어 이 채널들을 넣어 두면 보기 편하다 (섹션은 사용자가 직접 만들어야 함).
- 메시지 형식 (예시):
  ```
  🏠 [LH] 2026년 행복주택 입주자 모집공고 (서울 강남권)
  📅 게시일: 2026-10-24 | 마감: 2026-11-07
  🔗 https://...
  ```
- 같은 회차에 새 공고가 여러 개면 한 메시지로 묶어서 보낸다.
- 새 공고가 없으면 알림을 보내지 않는다 (옵션: "오늘은 신규 공고 없음" 메시지).

### F4. Obsidian 아카이빙 (Archiver)

- **Obsidian MCP** ([MCPVault](https://github.com/bitbonsai/mcpvault) `@bitbonsai/mcpvault@0.16.0`)로 볼트에 노트를 쓴다.
  - 볼트 경로: `/Users/yoomac/Documents/Obsidian Vault`
  - 볼트 파일을 직접 다루기 때문에 Obsidian 앱이 꺼져 있어도 되고, 플러그인이나 API 키도 필요 없다.
  - 사용할 도구: `write_note` (노트 생성), `update_frontmatter` (상태 갱신), `search_notes`·`get_frontmatter` (기존 공고 조회)
- 공고 1건당 Markdown 노트 1개를 만든다.
- 폴더 구조 (안):
  ```
  <Vault>/주택공고/
    ├── SH/
    ├── GH/
    └── LH/
        └── 2026-10-24 행복주택 입주자 모집공고.md
  ```
- 노트 형식: YAML frontmatter + 본문
  ```markdown
  ---
  source: LH
  id: "2026-000123"
  title: 2026년 행복주택 입주자 모집공고
  category: 임대
  posted_at: 2026-10-24
  deadline: 2026-11-07
  url: https://...
  tags: [주택공고, LH, 임대]
  ---

  # 2026년 행복주택 입주자 모집공고

  - 원문: [링크](https://...)
  - 첨부: ...
  ```
- frontmatter를 넣어 두면 Obsidian Dataview 같은 플러그인으로 기관별·마감일별 목록을 볼 수 있다.

### F5. 스케줄링

- 하루 1회 이상 자동 실행 (기본: 매일 오전 9시, 시간은 결정 필요).
- 에이전트는 Slack·Obsidian MCP가 연결된 Claude(Claude Code)가 정해진 시간에 실행하는 방식이다.
- 실행 환경 후보:
  - **로컬 Mac (Claude 데스크톱 앱 예약 작업 또는 launchd + `claude -p`):** Obsidian MCP가 로컬 볼트에 바로 접근할 수 있어서 가장 간단하다. 단, Mac이 꺼져 있거나 잠자기 상태면 실행되지 않는다.
  - **클라우드 (원격 예약 에이전트):** 항상 실행되지만, Obsidian MCP가 로컬 볼트에 접근할 수 없어서 Git 동기화 같은 별도 연동이 필요하다.

### F6. 오류 처리

- 특정 기관 수집이 실패해도 나머지 기관은 계속 처리한다.
- 수집에 실패하면 Slack에 오류 알림을 보낸다 (예: "GH 수집 실패: 사이트 구조 변경 가능성").
- Slack 전송이 실패해도 Obsidian 저장은 진행하고, 다음 실행 때 다시 보낸다.

## 7. 비기능 요구사항

- **안정성:** 사이트 구조가 바뀌면 조용히 0건이 되지 않고 오류로 감지되어야 한다.
- **예의 있는 수집:** 요청 간격을 두고 하루 몇 번만 조회해서 대상 사이트에 부담을 주지 않는다.
- **보안:** Slack 인증은 Slack MCP 커넥터의 OAuth로 처리해서 토큰을 코드나 파일에 두지 않는다. 그 밖의 API 키(예: 공공데이터포털)는 `.env`로 관리하고 Git에 올리지 않는다. Obsidian MCP는 볼트 폴더 밖에는 접근하지 못한다.
- **의존성 고정:** MCP 서버 패키지는 버전을 고정해서 쓴다 (`@latest` 금지).
- **유지보수성:** 기관별 수집기를 같은 인터페이스로 만들어, 나중에 다른 기관(예: 청약홈, 인천도시공사)을 쉽게 추가할 수 있게 한다.

## 8. 시스템 구성 (개요)

```
[Scheduler] ──▶ [Claude 에이전트]
                        │
                        ▼
              [Collectors: SH | GH | LH]
                        │
                        ▼
                 [Dedup / State Store]
                        │ (신규 공고)
              ┌─────────┴─────────┐
              ▼                   ▼
         [Slack MCP]        [Obsidian MCP]
     slack_send_message      write_note
```
